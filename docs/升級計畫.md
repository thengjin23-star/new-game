# 《一介散修》全面升級計畫

> 依據 0.17 版程式碼的全面檢查（2026 年 10 月）：實際讀程式與資料、跑全部測試、在 14 種解析度下用瀏覽器逐頁實測、以隨機長玩測試找錯誤。之後每一階段完成都會回來更新這份文件。

升級的原則：**保留現有成果 → 優化體驗 → 擴大世界 → 強化戰鬥 → 擴充技能 → 完善劇情**。每一階段都是一個能正常啟動、遊玩、存讀檔的版本；舊存檔一律相容。

## 二、哪些保留、哪些修改、哪些重構

**保留（核心已經好玩，不動骨架）**
- 即時戰鬥核心（combat.js）、施放方式的通用執行、敵人 AI、首領系統。
- 事件引擎（條件、選項、檢定、效果、排程）與所有劇情、人物劇情線。
- 修為、境界、壽元、靈根；裝備、煉丹、畫符、洞府；世界大事、勢力、宗門、秘境。
- 存檔格式（只做加法與遷移，不推倒）。

**修改（在原地改善）**
- UI：遮擋、溢出、字級、觸控範圍、彈窗互斥（Phase 1）。
- 戰鬥回饋：命中停頓、鏡頭震動、受擊硬直、擊殺回饋（Phase 3）。
- 內容密度：荒野、農田等大而空的區域（Phase 4、6）。

**重構（有計畫地換掉限制）**
- 技能：三格配招 → 技能收藏庫＋可擴充的快捷欄與技能組（Phase 2）。
- 世界：單一寫死的世界 → 地圖登錄表、多張地圖、按需建圖（Phase 4）。
- UI 程式：app.js 大閉包 → 新功能用獨立模組，舊頁面逐步拆出。

## 四、Phase 1（0.18）實作內容

**UI 健檢方法**：自動實測腳本在 14 種解析度（手機橫拿 568×320 到 932×430、直拿轉向 320×568 到 390×844、平板 1024×768 與 768×1024、電腦 1280×720 到 1920×1080）逐一走過：標題、建角、開場劇情、世界、提示訊息、行囊、修煉、見聞八個分頁、系統、地圖、歇息、懸賞榜、百煉坊、洞府、煉丹、畫符、戰鬥、長篇劇情、五個選項的劇情、結局、身死。每一頁自動檢查：按鈕被遮住、超出畫面、捲動框到不了最上面、文字被裁切、字小於 11px、介面互相重疊、介面佔畫面的比例。

**找到並修正的問題**
1. 第一次的指點泡泡蓋住按鈕：戰鬥時蓋住兩個招式和符，世界裡蓋住「術」，而且會攔下點擊。→ 移到整圈按鈕的上方，箭頭指向要說的那顆；點擊直接穿過它。
2. 直拿小手機（320×568）建角畫面無法捲動，按不到「就這樣吧」。→ 建角畫面在所有尺寸都能自己捲動。
3. 劇情選項欄、標題選單在內容太多時「置中」，最上面的選項捲不到。→ 有空間才置中，放不下就從頂端排起並可捲動。
4. 窄螢幕的提示訊息被放到狀態卡下面，蓋住地點、目標與搖桿；戰鬥時壓在首領血條上。→ 一律在狀態卡與選單之間；戰鬥時在對手血條下方，短螢幕則在自己的狀態卡下方、只留最新一則。
5. 狀態卡的日期在窄卡片裡從字中間斷行（「正月初｜一」）。→ 日期、時辰各自不斷行，窄螢幕省略「天元」二字；名字過長以「…」收尾；短螢幕的地點旗標保持一行，不再把目標推到搖桿上。
6. 氣血、靈力的字在血量低時看不清（淺字壓在淺底上）。→ 加深底槽、加強描邊；字級統一不小於 11px（原本 10px 的血條字、招式靈力、剋字、鍵位提示）。
7. 地點說明卡與「術」清單同在底部，可以同時打開而重疊；野獸靠近時說明卡被閃避鈕壓住；閉關時說明卡蓋在閉關條上。→ 兩者互斥；野獸靠近時收起說明卡；閉關時說明卡移到閉關條上方、狀態卡右邊（太長就捲動）。
8. 閉關條每秒整個重建，「提前出關」可能按到剛被換掉的按鈕而沒反應。→ 只建一次，之後只更新數字與進度條。
9. 窄而橫的手機（568×320）被當成直式，劇情與地圖改成上下排，可用高度不夠。→ 只有窄且偏直的頁面才上下排。
10. 「最窄螢幕」的規則用的是實體螢幕寬度，轉向後判斷錯誤。→ 改用頁面本身的寬度。
11. 頂端的目標與地點標籤太小，手指不好點。→ 觸控裝置上擴大可點範圍（外觀不變）。
12. 「減少動態效果」的系統設定沒有涵蓋提示、橫幅與指點。→ 一併關閉動畫。
13. 在頁面裡點了東西（裝備、使用、換招……），整頁跳回最上面。→ 同一頁重畫時，留在原來捲到的位置。

**穩定性**：新增隨機長玩測試（tests/soak.test.js），每次測試都會以多個種子隨機走動、互動、閉關、戰鬥、施放、存讀檔，確認沒有任何例外。

**架構準備**：見第六、七節「Phase 1 已做」。

## 四之二、Phase 2（0.19）實作內容

**做了什麼**
1. **技能收藏庫與快捷欄分開**（src/world/skills.js）。收藏庫從資料推出來、不另存：所有招式（17 招）與心法（9 門），學會的、沒學會的都列出，沒學會的寫著怎麼學；可搜尋（名字、流派、五行、說明）、照流派／類型／學會與否篩選、照預設／靈力／冷卻／名稱排序。
2. **快捷欄與技能組**：一組 4 格，煉氣 2 組、築基 3 組（`SLOTS`、`SETS` 兩個常數，要改格數或組數只改這裡）。沒動過的組自動配（學會新招自己換上，後面的組放前面的組沒放的）；先點格再點招（或反過來）放進去，同組重複就對調，✕ 清空，「戰鬥時先用這組」「交給系統自動配招」。
3. **戰鬥中**：四顆招式鈕、換組鈕（「壹／貳／參」，只有另一組有能用的招時才出現）；鍵盤 1–4、Tab。冷卻跟著招式走，換組不重置；施放到一半、戰鬥試煉中不能換；空格沒有鈕；換組會存檔。
4. **心法（被動技能）**（src/content/passives.js）：9 門，心法欄依境界 0／1／2／3／4 格；效果接在原有的鉤子上（傷害、靈力、冷卻、療傷、暴擊、減傷、回血、閃避冷卻、腳程、相生連招），不另開一套戰鬥計算。
5. **熟練度**：五級（初學、小成、精通、大成、圓滿），只在真正的戰鬥裡累積；每級威力 +5%、冷卻 −3%，8 招在某一級多出效果（穿透、更寬、燒更久、範圍更大、暈更久…）。
6. **新招「掌心雷」與新的施放方式「天雷」**：直接落在瞄準處、範圍傷害、打得對手一愣；瞄準預覽（淡藍落點）、落雷與地面閃光的畫、雷聲。取得方式接在世界裡：青石山雷擊木的新事件（雷雨天悟得，否則看悟性）。
7. **介面**：修煉頁分成修為／功法／技能三頁（修為滿了開修煉頁會先到「修為」，分頁上有紅點）；「技能」頁是第一個拆出 app.js 的頁面（src/ui/skillsPage.js）；技能圖示由程式產生（招名首字、五行顏色、施放方式記號）。手機上格子和招式離得遠：點了格子，頁面自己捲到招式；先點了招式，頁面捲回格子、四格都寫著「放進『某招』」；點沒學會的招式會說缺什麼。
8. **順手修正（所有選單頁）**：以前在頁面裡每點一下，整頁都會重播一次「從右邊滑進來」的動畫（看起來像閃一下）；現在只有剛打開時才滑進來。
9. **指點泡泡**：戰鬥的指點移到整組按鈕的左邊（寬度不超過按鈕與搖桿之間的空間）（上方現在有第四招與換組鈕）；小地圖、選單的指點在戰鬥按鈕出現時不出現（它們會蓋到換組鈕）；新增換組的指點。
10. **存檔**：新增 `player.hotbar`、`player.passives`、`player.skillXp`；舊存檔的三招自動成為第一組（第四格補上下一招），讀檔、匯出、雲端存檔都相容。

**原有功能受到的影響**
- 戰鬥按鈕：多了第四招（外圈左上）與換組鈕（最上面）；相生連招的字從第三招上方移到第四招上方，而且只在戰鬥中出現。
- 修煉頁：原本一長頁拆成三個分頁；原本的「戰鬥招式」卡由「技能」頁取代。
- 新存檔與沒配過招的存檔：第一組自動配四招（以前三招），所以一開打能用的招多一招。
- 戰鬥試煉：不變（照舊借你三招），也不累積熟練度。

## 四之三、Phase 3（0.20）實作內容

**做了什麼**（都疊在原本的即時戰鬥上，沒有第二套戰鬥系統）
1. **命中分級**：戰鬥核心把每一下記成一筆「命中」——普攻、重擊（連打第三下）、暴擊、招式、劍陣、擊倒（是否最後一個、是否首領）、你受傷（傷了幾成）、護體擋下、閃開、首領換階段。戰鬥本身不讀這些，畫面效果不會改變數值。
2. **打擊感**（新的 src/ui/feel.js）：命中停頓（普攻 0.02 秒到擊倒首領 0.16 秒，一層比一層重）、畫面震動（只動世界的畫布，按鈕不動）、擊倒最後一個對手時放慢約半秒（首領約一秒）、受傷時畫面邊緣變紅。停頓時世界以 0.04 倍速慢慢走，按下的東西立刻有效；輕的停頓不會連續疊加。
3. **設定**：系統頁「戰鬥手感」——畫面震動強／標準／弱／關、命中停頓開／關；系統設定「減少動態效果」時震動預設為關。
4. **普攻、重擊、暴擊三個層次**：命中的光芒四道、六道、八道金光加紅圈；數字一般、加大、寫「暴擊」並放大；聲音一般、多一記悶響、多一聲磬；震動與停頓逐級加重。
5. **招式命中各有樣子**：劍系（劍氣、劍影、飛劍、劍陣）一道白亮的切口與火花，劍氣飛行時有長斬痕與三道殘影；火球炸開、餘燼上飄；掌心雷電光亂竄；玄冰刺冰屑；狐火藍色火星；木系落葉；土系塵土；普攻墨點。護體施放時護罩從外圈收攏、六點光繞轉；擋下一擊泛起漣漪，破了會碎開。擊倒時墨點濺開、地上留墨跡，首領多一圈金光與重響。
6. **對手受擊反應**：被打中先白亮再轉紅、往後一縮；衝著你來時被打中會停 0.16 秒、退一步，之後有一段「韌性」時間不會再被打縮（一般 0.9 秒、鐵背熊 1.8 秒、山魈 1.2 秒）；重擊或暴擊能打斷正在蓄的招（之後 3 秒內不再被打斷）。首領不會被打縮或打斷；對手出完招的空檔不受影響。
7. **對手的戰鬥策略**：鐵背熊、山賊、山魈血少時發狠（更快、更痛）；武人血少時變謹慎（出完招就跳開、更常閃躲）；修士、執法弟子、武人、狐影會看見你的劍氣、法術、箭而橫跳躲開——讓「用什麼招打誰」有了差別。原有的狼群長嚎、過半潰散、首領換階段、山賊求饒與逃跑都保留。
8. **順手**：連招提示只在戰鬥中出現；選單頁裡點東西不再整頁閃一下（0.19 已修）；自動瞄準的招式會把「出手前蓄的那一下」也算進提前量——之前直衝過來的狼會從掌心雷底下穿過去。短螢幕（640×360）上第一次的指點出現時，提示訊息只留最新一則——之前兩則長的成就提示會往下疊到指點上。

**原有功能受到的影響**
- 戰鬥的節奏：每一下打中都會頓一下（很短），擊倒最後一個時放慢一瞬；不喜歡可以在系統頁關掉。

## 四之七、Phase 5（0.24）實作內容：美術升級

先訂風格指南（[docs/美術風格.md](美術風格.md)），再依「地面與道路 → 山岩懸崖 → 樹木與水面 → 建築與洞穴 → 人物與妖獸 → 技能圖示 → 天空與區域氛圍」一類一類改，每類改完都拍同樣的場景前後比對。沒有動存檔格式，也沒有動任何玩法數值；全部仍是程式繪製（2D 畫布筆刷＋WebGL 著色器），不需要任何圖檔，單頁版照樣能玩。

**立牌與樹的邊緣**
- 手機的高解析度螢幕不開多重取樣，樹、人物、妖獸的輪廓原本用硬性的透明度門檻裁邊，看得到階梯狀的鋸齒。改為在約一個螢幕像素內柔和淡出（只往內淡，不會露出原本被裁掉的淡影）。
- 樹木由近到遠畫（被擋住的部分不必再畫，濃密的樹林不會因此變慢）；柔邊隨著變薄轉成墨色，樹冠重疊處是一道細墨線，不是一道白邊。

**地面、道路、山岩懸崖**
- 地面：幾十步大小的墨暈（乾處偏暖偏淡、濕處偏深偏冷），近處加紙紋細點（低畫質關掉、遠處淡掉以免閃爍）；雪地上減弱。
- 凹凸明暗：每個地形頂點記下四周比它高或低，窪地與崖腳積墨、山脊與崖頂偏淡。
- 懸崖：順坡向下的長筆「斧劈皴」；西漠的砂岩有橫向層理；崖腳較深；陡壁上不再畫等高線（原本與皴紋疊成格子）；崖頂描墨線。
- 道路：官道兩條斷續的車轍、斷續的路邊墨線、路邊碎石；小徑的邊緣參差。
- 石頭：由一團黑墨改為淺灰的石面，右側受光、底部積墨、一道轉折線與皴紋。
- 西漠的戈壁：顏色改淡並畫上深淺石子（原本的深色大塊看起來像污漬）。

**樹木與水面**
- 樹冠分出三個明度：左下墨影、中間葉色、右上受光（春夏暖黃綠、秋天暖黃、冬天淡灰白）；黑風林的樹由近乎全黑改為深綠；松針上緣受光。
- **你走進樹林時，擋在你和鏡頭之間的樹變得稀疏**，看得見自己（戰場清出樹木也用同一種淡出）。
- 水面：深處緩慢的暗流濃淡、天光的淡色倒影；岸邊描一道墨線。

**建築與洞穴**
- 建築可以有「地方的蓋法」：南嶺青竹寨的住家、藥鋪、寨老的家、草屋改畫成**吊腳樓**（木樁架高、木平台與欄杆、木梯、木板牆、陡而深的茅草頂；寨老的家大一號、兩層屋頂、圍一圈竹籬）。房子的種類沒變，住在裡面的人與鋪子照舊。
- 地下（西漠的地宮、北原的礦坑）：畫面四周暗下來、上方壓著一片岩頂；**地宮的穹頂有一片微微閃爍的星圖**，走動時跟著緩緩移動。

**人物與妖獸**
- 人的受擊：被打中的一瞬間，整個人從腳往後仰、兩袖往外甩開（原本只是把圖往後推、壓扁）；人形的對手與你自己都是。

## 六、技能系統設計（Phase 2）

**最重要的原則：「學會多少招」和「快捷欄放幾招」是兩件事。**

- **技能收藏庫**（由資料推導，不另存）：所有招式依流派分類（通用、劍修、法修、體修、法器、符修…），每招顯示名稱、圖示、說明、靈力、冷卻、施放方式、等級、學習條件（境界、功法、兵器、根骨、法器）與狀態（已學會／可學／未解鎖），可搜尋、篩選、排序。
- **快捷欄**：存在存檔裡的是「技能組」──每組固定數量的格子（手機 4–6 格、電腦 1–6 鍵），可以有多組並快速切換（例如劍修一組、法修一組）。格子數量依裝置與操作調整，不為了數量塞滿畫面。
- **被動技能**：獨立的資料表與「心法欄」，提供增傷、減耗、冷卻縮減、移速、回復等持續效果，與主動招式分開。
- **技能等級與熟練度**：施放累積熟練度，升級改變傷害、冷卻或效果（不只加數值），資料先預留、逐步加內容。
- **取得方式**：境界、功法典籍、師父、宗門、洞府、秘境、遺跡、奇遇、戰鬥領悟──沿用現有的事件效果把技能接到世界探索。
- **存檔**：舊存檔的三格配招自動成為第一組；未解鎖、靈力不足、冷卻中、重複點擊都由施放核心把關，不靠介面。
- **施放核心不重寫**：新招式只要寫資料並選用既有的施放方式（直線、落地、自身、突進、周身、追蹤），有新的施放方式才擴充執行程式。

## 七、世界擴張設計（Phase 4）

**方向：多張相連的地圖，一次只載入一張。** 每張地圖約與現在的東荒一樣大，用渡口、山隘、傳送陣、飛行相連；總規模擴大到約五倍。
- 為什麼不直接把一張圖放大五倍：實測建圖時間會從約 1 秒變成約 5 秒（在手機上更久），尋路、霧、整張世界的縮圖與立體地形的記憶體都跟著放大；而且會讓現有座標、存檔的霧與大量測試全部失效。
- 多張地圖的好處：每張圖的建圖成本固定、現有座標與存檔不動、可以一張一張做完再開放，也符合故事（白鶴渡就是第一章的出口）。

**Phase 1 已做**：把散在各模組、寫死的世界格數（130／115／40）改成共用常數。

**Phase 4 的步驟**
1. 地圖登錄表：每張地圖的尺寸、區域、地形特徵、地點、人物、妖獸、資源、音樂、氛圍集中登錄，新增區域不必改十幾個檔案。（0.21 完成）
2. 世界資料改成「每張地圖一份」，換圖時重建渲染器；存檔加上目前地圖與各圖的霧（版本化遷移，舊存檔原樣搬入東荒）。（0.21 完成）
3. 建圖預先計算或在背景執行，換圖有過場畫面。（0.21：過場的幕已做，建圖在幕後進行；南嶺的地形與地勢在測試機的 Node 上約 0.3 秒，瀏覽器另外要重建立體畫面）
4. 依序開放新地圖（每張先有內容密度，再開放）：南嶺（0.21，已開放）→ 西漠（0.22，已開放）→ 北原與東荒補密度、地圖和修為的連動（0.23，已開放）。

## 八、美術升級方向（Phase 5）

- 先訂**風格指南**：色彩系統（紙色、墨色、單一朱紅強調）、光源方向（左上）、陰影與描邊、角色比例、地形細節、特效風格、建築形制。
- 依序提升：地面與道路 → 山岩懸崖 → 樹木草地 → 水面 → 建築與宗門 → 洞穴遺跡 → 人物與妖獸 → 道具靈草 → 技能特效 → 天空霧氣光影。
- 各區域氛圍：森林濃密與霧、遺跡殘破與符文、靈脈靈光、禁區壓迫的色調與聲音。
- 素材：目前全部程式繪製；畫好的圖（含 AI 生成）可放入素材槽（[assets/README.md](../assets/README.md)），但必須符合遊戲視角、尺寸、透明背景與動畫切格，不能用一整張場景圖代替可行走的世界。0.24 起這個環境加入了 AI 繪圖外掛 SpriteCook（需要登入、會扣它的點數）；最適合的是技能圖示、道具圖示、事件插圖與人物頭像，打算先小量試做、和程式繪製的畫面並排比較，風格合得來才擴大使用。單頁版不讀素材資料夾，生成的圖只能少量內嵌。
