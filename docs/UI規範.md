# 《一介散修》UI 規範

> 0.18 起適用。新介面一律照這份做；舊介面在各階段順手對齊。數值都對應 `styles/main.css` 開頭 `:root` 的變數，改規範時一起改變數。

## 一、風格

- 宣紙底、墨色字、**唯一的強調色是朱紅**（`--red`），另有玉綠（`--jade`，好的、修煉、閃避）、赭黃（`--ochre`）、紫（`--violet`，系統的聲音）。
- 東方修真的味道來自字體（霞鶩文楷）、紙色、朱印、毛邊與水墨，**不靠裝飾把字擠小**。閱讀性永遠優先。
- 卡片是紙：淺色半透明底、細墨線框、小陰影；按鈕是印：實心墨色或朱紅，或細框。

## 二、字級（`--fs-*`）

| 變數 | 大小 | 用在 |
|---|---|---|
| `--fs-xs` | 11px | **最小可用字級**：血條上的字、徽章、鍵位提示。任何字都不得小於它 |
| `--fs-sm` | 13px | 次要說明、標籤、註記（`.small`、`.chip`） |
| `--fs-md` | 14px | 小按鈕、頁面裡的清單 |
| `--fs-body` | 16px | 頁面內文 |
| `--fs-story` | 17px | 劇情文字（行高 1.9） |
| `--fs-title` | 24px | 頁面標題 |

- 次要文字用 `--muted`（對紙色至少 4.5:1）。不要用更淡的灰寫長段說明。
- 數字用 `font-variant-numeric: tabular-nums`，跳動時不晃。

## 三、間距、圓角、觸控

- 間距只用 4 的倍數：`--sp-1` 4、`--sp-2` 8、`--sp-3` 12、`--sp-4` 16、`--sp-5` 24。
- 圓角：小元件 `--radius-s` 6，卡片 `--radius-m` 10，膠囊 999px。
- **手指至少要 `--tap`（44px）**。外觀做不到 44px 的小東西（頂端的目標、地點標籤），在觸控裝置上用透明的 `::after` 擴大可點範圍。

## 四、資訊層級

1. **一直在的**：左上狀態卡（名字、境界、靈石、日期時辰、修為、氣血、靈力）、地點與旗標、目標；右上小地圖與選單。
2. **戰鬥時換成**：左上戰鬥卡（氣血、靈力、狀態），正上方對手血條，右下普攻與招式環。日期、地點、選單收起。
3. **臨時的**：提示訊息（自動消失）、橫幅、第一次的指點（點擊穿透、7 秒消失）、地點說明卡、「術」清單。
4. **打開的頁面**：行囊、修煉、見聞、系統、地圖、劇情。打開時，底下的一切暫停並變暗。

## 五、畫面分區（橫式）

```
┌──────────────┬────────────────────┬──────────┐
│ 狀態卡        │ 提示訊息（置中一欄）   │ 選單 小地圖 │
│ 地點・旗標     │ 戰鬥時：對手血條在上， │          │
│ 目標          │ 提示在血條下方        │          │
│              │                    │  指點泡泡  │
│  （搖桿區）    │   地點說明卡／術清單   │  招式環    │
│   ◯          │                    │    ◉     │
└──────────────┴────────────────────┴──────────┘
```

- 每一區只放屬於它的東西；**新東西先找區，不要疊在別人的區上**。
- 左上那一疊不得壓到搖桿（短螢幕時旗標只留一行）。
- 底部中間同一時間只能有一個：地點說明卡或「術」清單；閉關時說明卡移到閉關條上方、狀態卡右邊（太長就捲動）；野獸靠近時收起說明卡。
- 提示訊息永遠在狀態卡與選單之間的那一欄；戰鬥時在對手血條下方，短螢幕（高度 ≤ 420）則在自己的戰鬥卡下方、只留最新一則。
- 指點泡泡在整圈按鈕的**上方**，箭頭指向要說的那顆，點擊會穿過它。戰鬥時（0.19 起上方有第四招與換組鈕）指點改在整組按鈕的**左邊**；小地圖與選單下面的指點在戰鬥按鈕出現時不出現。
- 戰鬥按鈕（單位是招式環的半徑 `--ring`，從大鈕中心往左、往上量）：招式一 (1, 0)、招式二 (0.71, 0.71)、招式三 (0, 1)；外圈：閃避 (1.72, −0.3)、藥 (1.82, 0.34)、符 (1.48, 0.98)、招式四 (0.9, 1.58)、換組 (0.3, 1.72)。新按鈕先在這張表裡找位置，算過和鄰居的距離再加：最短的頁面（568×320，`--ring` 84px）上，兩顆按鈕的外框（正方形）也不能重疊。

## 六、圖層（`--z-*`，由下到上）

| 變數 | 值 | 是什麼 |
|---|---|---|
| `--z-hud` | 5 | 狀態卡、地點、目標、小地圖、提示訊息、走路提示 |
| `--z-hands` | 6 | 搖桿、圓鈕、閉關條、戰鬥卡 |
| `--z-pop` | 7 | 地點說明卡、術清單、戰鬥按鈕 |
| `--z-menu` | 8 | 選單 |
| `--z-coach` | 9 | 第一次的指點 |
| `--z-layer` | 20 | 頁面、劇情、身死、結局 |

不要再寫數字的 z-index；新東西選一層，或在這張表加一層。

## 七、彈出視窗與頁面

- 頁面不得超出畫面：高度用容器的 100%，**內容自己捲動**（`overflow-y: auto`）。
- 會捲動的框**不可以用 `align-content: center` 置中**：內容一多，最上面就捲不到了。要置中時用彈性欄（flex column）加上下兩個 `flex: 1 0 0` 的空白偽元素（見 `.ev-side`）。
- 資訊太多就分頁（`.sheet-tabs`、`.subtabs`）、分類、展開或捲動，不要全部塞在同一個畫面。
- 關閉鈕固定在頁首右側；劇情的選項在右欄（窄而直的頁面改成在下方）。
- 頁面裡點了東西而整頁重畫時：留在原來捲到的位置，**不重播**打開時的滑入動畫（只有新打開的頁面才滑進來）。
- 要使用者「先點這裡、再點那裡」的兩步操作，兩處在小螢幕上離得遠時，第一步之後自動捲到第二步的地方，並在第二步的目標上標出會發生什麼（見技能頁）。

## 八、文字溢出

- 名字、物品名等單行：`white-space: nowrap; overflow: hidden; text-overflow: ellipsis`，並給容器 `min-width: 0`。
- 日期、數值這類「斷在中間就看不懂」的片段：各自 `nowrap`，讓整段換到下一行。
- 長段文字照常換行；長篇劇情在自己的欄裡捲動。

## 九、斷點（一律用容器查詢 `@container app`，以「頁面」大小為準）

- 手機直拿時整個畫面轉成橫的，所以**頁面永遠是橫的**；判斷大小要用頁面本身，不要用 `@media` 量實體螢幕。
- `max-height: 420px`：短螢幕（橫拿的手機）。提示最多兩則、字小一號；旗標一行。
- `max-height: 340px`：很短的螢幕（568×320）。指點泡泡更窄。
- `max-width: 600px`：很窄的頁面。日期省略「天元」、提示字小一號。
- `max-width: 620px and max-aspect-ratio: 5/4`：**窄而且偏直**（電腦上的窄視窗）才把劇情與地圖改成上下排；窄而橫的手機維持左右排。

## 十、驗收

每個版本都用自動實測腳本，在 14 種解析度（568×320 到 1920×1080，含直拿轉向與平板、電腦）走過所有主要畫面，檢查：

- 按鈕被遮住；
- 東西超出畫面；
- 捲動框的最上面捲不到；
- 文字被裁切；
- 字小於 11px；
- 介面互相重疊。

主要畫面也要截圖目視檢查。
